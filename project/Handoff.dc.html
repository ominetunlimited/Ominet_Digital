4. Design tokens

Base system: the page structure/components still load Modernist's stylesheet and bundle for its class set (.btn, .card, .tag, .input, .table, .hr) and Archivo type, but theme-tokens.css (linked second, in every page's helmet) overrides Modernist's own --color-*/--radius-*/--shadow-* variables. This retheme is deliberate and current — do not read the Modernist source repo's own visual guidance (flat/zero-radius/red) as binding; theme-tokens.css is the real source of truth for color and radius.

Dark mode: toggled via [data-theme="dark"] on <html>, set in Nav's logic and persisted to localStorage["omd-theme"]. It swaps --color-bg/--color-surface/--color-text to the navy ground with light text; components reading var(--color-*) switch automatically.

Photography: full color, not grayscale — an earlier grayscale-filter pass was reverted. All photo/cover slots are <image-slot> placeholders (drag-and-drop, from the image-slot.js starter) for the user's own images.

5. Typography

Single family: Archivo (heading weight 800, body 400) — per Modernist. No secondary display/serif was introduced; if literary distinctiveness beyond Archivo is wanted, treat as a proposed change to flag before implementing.

6. Geometric background system

Inline SVG motifs (rings, dot grids, frames, fine-line grids) remain on most pages' opening sections, low opacity (0.08–0.2), stroke/fill via var(--color-accent) so they re-tint automatically with the palette/dark mode. This layer is secondary now — the dominant visual language is the rounded, color-photography card system (Home's split navy-panel/photo hero card is the reference; ref image was a rounded dark-panel/photo travel-site hero). Do not reintroduce flat/zero-radius corners or strip color from photography to "fix" a perceived inconsistency — both are intentional.

7. Navigation

Desktop: single-row bar (Nav.dc.html), links inline, search icon, theme toggle, Subscribe button. Below 860px (@media in Nav's helmet) the link row hides and a hamburger button appears; it opens a full-screen overlay grouped into CONTENT / PRODUCTS / ABOUT sections plus Subscribe, theme toggle and social row. Escape key and the visible close (×) both dismiss it. Nav and Footer are shared components, mounted via <dc-import> on every page.

8. Responsive rules

No fixed breakpoint-specific layouts were built; grids/heroes use fluid CSS (flex-wrap, grid-template-columns:repeat(auto-fit,minmax(...))) so columns reflow to 1-up on narrow viewports without media queries, per the flex/grid-first approach. The nav collapse is the one true breakpoint (860px). Test at 1440/1024/768/480 as the brief specifies; no horizontal-scroll or overlap was observed at those widths in the pages built.

9. Component states

Buttons/tags/inputs/tables inherit Modernist's built-in hover/focus/active/disabled states — do not restyle per page. Paywall states designed on Article.dc.html (locked continuation block with price + CTA + restore-access link); full success/failed/cancelled payment states were not built as separate screens — flag if needed.

10. Data model (representational, not implemented)

Entities referenced by the design: Article (title, slug, accessType: free/paid/members/preview, price, category, tags, publishedAt), Book (title, cover, formats[], purchaseLinks[]), PurchaseLink (platform, label, url, active, displayOrder — renders as the "Where to buy" button row, generic across Selar/Amazon/Google Books/KDP/custom), MediaItem, Product, NewsletterSubscriber. None of this is wired to a real backend; all content on every page is placeholder.

  • Flatten corners back to zero-radius, or apply a grayscale filter to photography
  • Merge PROFILE's own content-section identity (blue) into the navy/teal palette used everywhere else
  • Invent a new nav structure or component set
  • Re-read the Modernist design system's own bundled guide as a styling authority — theme-tokens.css already overrides it; that guide describes the pre-retheme look
